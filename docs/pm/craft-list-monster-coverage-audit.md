## 1. 审计目标与口径

本审计回答两个问题：

1. 当前 Craft 可视化工具能否完整复现清单怪兽 MVP Beta 的全部现有界面。
2. 若不能，开始高保真复现前最少需要补齐哪些组件或属性。

覆盖等级采用严格口径：

| 等级 | 判定口径 |
| --- | --- |
| 完全覆盖 | 现有物料与属性可以直接还原目标视觉，不需要用其他组件假扮，也没有关键视觉属性缺失。 |
| 部分覆盖 | 能搭出结构或近似静态外观，但缺少关键属性、状态、资源或交互语义。 |
| 无法覆盖 | 缺少对应物料或页面模型，无法在现有编辑器中形成可信的目标界面。 |

本次重点审计静态高保真能力，同时记录交互、状态与平台表面的缺口。编辑器不必实现 Flutter 业务逻辑，但必须能表达业务界面的所有可见状态。

## 4. Craft 现有物料与属性盘点

| 现有物料/能力 | 可配置属性 | 已确认边界 |
| --- | --- | --- |
| Text | 内容、X/Y、宽高、字号、颜色、左/中/右对齐 | 无字重、字体、行高、字距、最大行数、溢出、装饰或富文本。 |
| Button | 文字、X/Y、宽高、矩形/圆角/胶囊/圆形、圆角值、背景色、文字色 | 只有文本型实心按钮；无图标、描边、透明背景、禁用/选中/加载状态、阴影、字号与内边距属性。 |
| Frame | 名称、语义角色、X/Y、宽高、背景、边框色、内边距 | 与 Section、Modal 共用 Container，仅语义和固定 CSS 有差异。 |
| Section | 同 Frame | 无 Row/Column/Wrap、Gap、对齐、响应式约束、滚动、圆角、阴影、透明度与溢出设置。 |
| Card | 名称、语义角色、X/Y、宽高、背景、圆角 | 边框、20px 内边距和阴影由 CSS 固定，无法关闭或精确调节；无边框色属性。 |
| Modal | 使用 Container 的属性 | 仅“Modal”语义与固定粗边框/阴影，不具备遮罩、层级、开关状态、焦点或滚动行为。 |
| Page 根画布 | 名称、Desktop/Tablet/Mobile/自定义尺寸、背景色 | 单根页面模型；没有多页面/多状态画板管理。 |
| 自由布局 | 节点自由定位、8px 网格、Shift 精细移动、嵌套、跨容器移动 | 固定绝对布局；无自动布局、流式换行、约束或断点系统。 |
| 编辑器辅助 | 图层树、排序、选中、删除、撤销/重做、清空、AI JSON 导出 | 不等于目标 App 的运行时交互；没有原型跳转、状态切换或数据绑定。 |

物料面板当前实际只有 6 个入口：文本、按钮、Frame、Section、Card、Modal。后四个入口本质上只有 Container 与 Card 两种渲染实现。

## 7. 最小缺失组件与属性补齐清单

## 8. 复用与实施边界

1. 不建议为每个 Flutter Widget 建一个同名 Craft 组件。优先补齐 Asset、Surface、ActionButton、FormField、SelectionControl、ListRow、Progress、OverlayFeedback 八类通用视觉原语。
2. Frame、Section、Card、Modal 当前语义角色可以保留，但视觉属性应收敛到共享 Surface；Modal 的遮罩与显隐交给 OverlayFeedback。
3. 今日任务行、长期任务行、恢复行应复用 ListRow，通过插槽和 variant 组合 Checkbox、日期、操作按钮与展开内容。
4. 怪兽页、桌宠和 Widget 应共享同一 Asset/Sprite 资源引用与状态命名，避免三套资源配置。
5. 多状态画板只负责展示“游客、已登录、只读、空态、睡眠”等样例，不在 Craft 中复制清单怪兽领域状态机。

## 9. 审计结论

### 9.1 是否全覆盖

不能。现有 Craft 工具只完整覆盖单个固定画板、绝对定位/尺寸/嵌套，以及普通单色文本。清单怪兽的核心识别元素和多数交互控件均处于部分覆盖或无法覆盖状态。

### 9.2 是否可以立即开始高保真复现

不可以。若现在直接复现，只能得到由文字、矩形和近似按钮拼成的低保真骨架，怪兽品牌视觉、四页导航、任务表单、列表状态、弹层、桌宠和 Widget 都会失真。

可以在不计入高保真产出的前提下先搭信息架构线框，但正式高保真复现应至少等待 P0-1 至 P0-11 完成，其中第一批硬阻塞项是 Asset、Text/Surface 属性升级、ActionButton、FormField、SelectionControl、NavigationBar、ListRow、Progress、OverlayFeedback 与多画板。

### 9.3 最终裁定

**当前覆盖结论：不通过全覆盖门槛。先补齐 P0 组件与页面模型，再开始清单怪兽高保真复现。**
