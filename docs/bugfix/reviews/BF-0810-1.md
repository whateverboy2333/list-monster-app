## 历史数据流与 5 Whys（毫秒方案，已被 User Gate 否决）

1. 为什么时间肉眼不变？保存前后的成功状态字符串相同。
2. 为什么字符串相同而磁盘时间已变？两次 ISO `savedAt` 落在同一自然秒。
3. 为什么不同 ISO 时间映射相同？Topbar 原先只显示 `HH:mm:ss`，丢弃毫秒。
4. 为什么新保存没有其他可见差异？成功反馈仅由秒级时间字符串表达，revision 不参与文案。
5. 为什么原回归未拦截？它只断言“已保存”存在和 savedAt 有效，未比较同秒前后及响应/磁盘/界面三点映射。

根因已由边界实验证实：App 成功分支正确采用响应 `savedPayload.savedAt`；同秒时旧格式折叠、跨秒时同一路径立即变化。最小修复只提升 Topbar 的真实本地时间精度到 `HH:mm:ss.SSS`，无需改 App、schema、服务、存档协议或保存边界。
